# Populate

Read `../session-plan/SKILL.md` and its command reference. Keep your current identity.

Apply the entry skill's preparation guidance to frame the session, then [Develop a component](../session-plan/SKILL.md#develop-a-component) for each unit. Questions within a component can be part of its useful first contribution.

Use the helper to create the named session with saved intake, if it does not exist. Read its reference material. Write each substantive unit as plain Markdown with Context, Content, optional Options, and Recommendation where useful. Units may be decisions or components being developed. Preserve detail and connections without inflating the number of cards.

Use `add` for each user-directed unit. It consumes the pre-created blanks and obtains more mechanically; never ask the user to manufacture blank cards or edit metadata. Apply the entry skill's Useful initiative guidance and use `propose` for worthwhile unsolicited additions. Follow its first-board handoff guidance when returning the verified URL, distinguishing ready-to-review work from a provisional preview.

When presenting choices, make the recommended action clear and distinguish optional additions from that action. Staging accepts the recommendation by default; a qualification can override it. A card may still be a substantive component rather than a choice.
